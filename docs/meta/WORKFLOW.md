# 工作流（五环节 + 环节⑥）

> 里程碑 v2 工作流定义：设定 → 机制 → JSON → 分析 → 重设计 五环节迭代，周期性骨架重议（环节⑥）。

## 五环节

| 环节 | 名称 | 产出 | 门槛 |
|---|---|---|---|
| ① | 设定补全 | 世界观/派系/英雄设定稿 | 主人拍板入档 |
| ② | 机制落地 | 原语/触发点/规则扩容提案（`meta/骨架重议.md` 登记） | 环节⑥ Gate 通过 + SCHEMA.md 登记 |
| ③ | 技能池 JSON | `docs/json/faction_NN.skills.json` 卡面 | schema（结构）+ validate（语义）+ check_enum_sync + check_glossary + lint 全绿 |
| ④ | 分析评分 | 结构评分与蓝图兑现报告 | 评分只诊断结构，不作平衡依据 |
| ⑤ | 重设计迭代 | 逐英雄/逐轴改卡 | 四脚本全绿 + 分数不回落 |

## 环节⑥：骨架重议

- 命题撞车（两条玩法骨架塌成一条）时**先换骨架**，不在既有骨架内硬叠机制。
- 机制扩容请求与拍板记录统一登记 `meta/骨架重议.md`。
- 新机制准入纪律：先登记 SCHEMA.md 原语表/触发点表 → 改 schema → 全链（DDD 参数篇 + glossary + 校验脚本）同步 → 数据才可用。

## 迁移期专项纪律

1. 从 CardGame 参考源（只读）取卡必须登记 `meta/迁移映射表.md`（新卡 id ↔ 旧途径/旧卡 id ↔ 改动类型）。
2. 去 IP：name/describe 机制化表述；删 lore/flavor；占位符命名（派系·壹…玖 / 英雄·壹…玖）。
3. 数值「随迁移再定」：旧数值默认直迁，平衡标定是独立后续里程碑。
4. 每英雄迁移一个 commit；迁移顺序按 `meta/迁移映射表.md` 的派系序。
