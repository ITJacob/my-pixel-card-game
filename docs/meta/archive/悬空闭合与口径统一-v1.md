### 1.3 一条需要主人拍板的推定

`skill_warrior_s6_dawn_blade` 在 `docs/meta/迁移映射表.md` 里**没有对应条目**（该表 `s6` 只有 `s6_dawn_armor → h01_dawn_armor` 与 `s6_whetstone → j01_whetstone`）。回原项目只读核对：`docs/json/warrior.skills.json` L927–L938 表明它是一张 `kind:"equipment"` 的「晨曦之剑」（装备武器、攻击 +4、附加无元素伤害），v2 中无同名卡、也无同语义卡。

裁定为 `j01_standard_blade`，依据是三条可核事实，不是同名迁移：

1. 三条 `modify_skill` 载荷完全一致（`selector:by_id`、`setOpportunity:0`、note 均写「立即拔刀，本次行动机会不消耗」），构成一份拔刀白名单；
2. `docs/json/family_01.skills.json` 当前**恰好 3 张** `kind:"equipment"` 卡：`j01_standard_blade` / `j01_silver_rapier` / `j01_twilight_greatsword`，第 8、9 条已占后两张；
3. `docs/json/hero_01.skills.json` 的 `h01_battle_authority` `describe` 写「装备武器时立即拔刀」，是通用条件、不特指某一把剑；`battle_authority_draw` 的 `force` 白名单也只限「拔刀后仅可普攻」，不绑定具体武器。

即：按**当前卡池三把武器全覆盖**做语义替代。**若主人认为白名单本应只有 2 条**（晨曦之剑在 v2 属有意删除），正确动作是删掉 `triggers[1].effects[4]` 整条 `modify_skill`，而不是换一个 id；本轮不擅自删载荷，留待一句话确认。

### 1.4 门禁化：让断链变成可抓的错误
