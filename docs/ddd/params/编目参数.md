# 编目参数与取值域

> 编目上下文机制层的取值域与纪律：展开纪律（原术语层的 v2 落点）、SkillDef 元标记、模板优先 + 逃生舱。Def/Grant 归属与 `$extends` 继承见 `contexts/编目上下文.md`；字段级结构权威是 `docs/json/schema/skills.schema.json`。v2 无独立术语字典层（无 TermDef 池）——术语纪律落在 3 算子的编目期行为上。

## 一、展开纪律（原术语层的 v2 落点）

- `sequence` 编目期展开为扁平 EffectRef 链，运行期引擎零感知；展开在校验时一次性完成，运行期不再解析嵌套结构。
- `repeat` 动态段数：`countFrom:'statusStacks'` + `statusId` 读持有层数；按上限（maxStacks / countMax）编目期展开，运行期按实际值执行前 N 段——「层数段数」「按 debuff 条数累加」依此语义。
- **多段共享坐标**：repeat 默认共享同一冻结坐标（`shareTarget`），段间不重新解析目标；目标死亡则后续段落空。
- **文案同步**：展示文案由实际生效参数渲染，禁止与实参脱节——真打三下就必须显示三下，或改名。
- **互斥概率分支**：写成嵌套 if 链（各分支 condition 互斥、抽样只在判定处读一次，R4）；禁止并列多个独立概率 if（叠加触发）。细节见 `contexts/随机性治理.md` §三。
- **跨效果传值**（吸血等）不走算子内传参，做成独立原语（drain）。

## 二、SkillDef 元标记

> 本节只定语义与运行态边界；字段结构、取值封闭集与必填以 `docs/json/schema/skills.schema.json` 的 `$defs/card` 为准，`rarity ↔ sequence` 的派生基准以 `docs/json/manifest.json` 的 `rarityMap` 为准。

| 标记 | 取值（机器正源见 schema） | 说明 |
|---|---|---|
| `tags` | string[]，开放 | 风味与流派检索标签，也是规则增强按 tag 过滤的读取面；`$extends` 继承取父∪子并集（`contexts/编目上下文.md`）；新风味一律走 tags，不新开元素或字段 |
| `authority`（权柄） | boolean，默认 false | 权柄标记：schema 暂未设字段，旧机制登记于此，复活 echo 限制时补登记。机制语义：模仿/复制/重放类效果（echo_last_skill 等）默认排除权柄技能；纯数据标签，不参与结算 |
| `sequence` | integer 0–9，位次档 9→0 | 卡级位次标记；`rarity` 由它经 `manifest.json` 的 `rarityMap` 派生，不得两写。与「一、展开纪律」及 `contexts/效果上下文.md` 的 `sequence` 算子同名不同物 |
| `rarity` | 五值封闭集 | 稀有度检索/展示标记，由 `sequence` 派生而非独立配置项；派生不符由 `validate_schema.py` 拦截 |
| `axis` | string，构筑轴 id | 构筑检索轴，不是规则读取面（按 tag 过滤读的是 `tags`）。schema 描述称须存在于顶层 `axes` 键，机器侧当前只校验必填、未建 axes 池与白名单校验（欠账见待办） |
| `flagship` | boolean | 该构筑轴的代表性卡标记；纯检索/展示 |
| `tentative` | boolean | 定稿状态标记；schema 写「默认 true」，实测全库卡片均显式写 false，二者不构成冲突，但默认值语义待命名专项同步 |

- **不进结算**：本节全部字段都是编目期元标记，不进运行态 Unit、不进 Action 载荷、不参与 I→R→M→O，不得被条件谓词或 `valueFrom` 读取；INV-3 冻结的是运行态，与它们无关。
- **同名消歧**：判别只看所在对象——card 顶层的 `sequence` 是整数位次档，效果树节点上 `op:"sequence"` 是顺序执行算子；二者不得互相引用或互相推导。
- **必填 ≠ 结算依赖**：五字段在全部卡上均为必填（`validate.py` 必填列表），但那属于编目完整性，不构成运行态读取许可。

## 三、模板优先 + 逃生舱

- 技能定义**优先 `$extends` 复用**父定义（只覆写差异字段），享复用与继承 tag 查询；**无法模板化的**允许不带 `$extends`、由卡自带完整定义——特异技能有出路，不堵死。
- **战内分支选择**（三选一/四选一）：正典 = 卡面顶层分支结构（if / 分支 sequence），不立变体（modes）机制；战外构筑变体归战外上下文，不进战斗内核。
- **流派** = 基于 tags/元素的查询规约（如「含某 tag 的技能 ≥ 2」），纯查询，不进战斗。

## 四、数值单点

默认值与上下限只在 Def，实例值只在 Grant/params；任何重复定义视为配置错误（Def→Grant→Instance 三件套，见 README）。卡面只写实例参数，unitType/基线/技能组由顶层蓝本池兜底，不两写。

## 五、设计注记（note）溯源口径

- **字段定位**：`note` 是定义态条目上的人工设计注记，编目期可读、运行期不读；不参与结算、不进 Action 载荷、不属 INV-3 运行态冻结对象、不得作为条件谓词或 `valueFrom` 的读取面。机器侧只把它当字符串，不解析语义；引用完整性（INV-C1）只认 id 类字段，不认注记文本。
- **引用体系**：存量注记中形如 `文档名 §X` 的是**历史规格稿的编号锚点**。现行 DDD 正源是「无编号标题 / 中文分节 / 1.x 三级」三套并存，且 `执行上下文` 等文档名在现行 14 份正源中不存在；因此 § 编号不得作为正源定位依据。引用正源一律写「文档名 + 小节标题」，不带 § 编号。
- **历史编号封闭集**（存量一次性登记，由 `validate.py` 与 `check_enum_sync.py` 对账；表内均为数字编号）：

| 历史编号 | 引用来源举例 |
|---|---|
| `1.1` | 效果参数 |
| `1.1b` | 编队参数 |
| `1.2b` | family_14 裸引（无文档名） |
| `1.4` | 共享内核参数 |
| `2.1` | 执行参数 |
| `2.2` | 执行参数 / global 裸引 / 编队参数 |
| `2.4` | 编队参数 |
| `12` | 执行参数 |

- **中文分节编号**：`§一` / `§三` / `§四` 等按现行 params 的中文标题人工核对（部分可对应，部分为历史稿残留），机器侧不解析中文编号。
- **禁止扩散**：数字 § 编号只允许落在上表封闭集内；出现未登记编号即编目期报错。机器侧只能冻结编号集合，无法区分「新写」与「存量」，因此「新写注记不带 § 编号」是人工纪律，由本节约束。存量注记（规模与清单见待办）一次性豁免，不逐条改写、不把设计过程注记升格为权威引用。
- **待授权动作**：把存量注记逐条改写为「文档名 + 小节标题」属数据侧批量动作，须单独授权，按 1 条样例验收后全量推进；不得由本节推定映射关系。
- **失败态**：按历史编号查现行正源 → 查不到条款；机器按注记定位 → 定义态引用解析被文本污染；新编号持续扩散 → 溯源体系永不收敛。
