# 执行参数

> 16 触发点封闭集（INV-18）+ 计时口径。

## 触发点（passive_hook / trigger.event 同域）

| 触发点 | 时机 | 语义要点 |
|---|---|---|
| on_battle_start | 战斗开始 | 开局装备/快照类 |
| on_turn_start | 获得行动机会 | 机会括号左端 |
| on_turn_end | 机会结束 | 机会括号右端；wasted 也闭合 |
| on_apply | 状态挂载时 | 挂载即 fire |
| on_remove | 状态卸载时 | 可按原因过滤（expired/dispel/consumed/overwritten）；配合溯源撤销 |
| on_tick | 每 tick | 高频钩子用 minIntervalTicks 节流 |
| on_phase_change | 相位变更 | 时钟跨边界或光照度覆写写入时 |
| on_spawn | 单位落场 | 含召唤物登场 |
| on_death | 单位死亡 | 死亡链入口 |
| on_kill | 击杀 | 击杀归因 |
| on_attack | 攻击行为 | 普攻/攻击类主动；会消耗武器耐久的语境 |
| on_equipment_equip | 装备牌装备时 | 实例建立后、战吼前 |
| on_active_skill | 主动技能施放时 | — |
| on_take_damage / on_deal_damage | 承伤/出伤 | 伤害链结算前后语境 |
| on_status_gain | 获得状态时 | 语义层强制登记制 |

## 载体规则

触发器只挂在持续存在的主体上：状态 StatusDef.triggers、被动 BehaviorTemplate、装备 equipment.triggers、召唤物 unitDef.triggers、界域 DomainDef.triggers。
**主动/召唤卡的顶层 triggers 不是合法载体**（一次行为没有持续监听语义）：瞬时后果写效果树 `if`，持续监听写入状态/装备/召唤物蓝本。

## 计时口径

| 字段 | 取值 | 说明 |
|---|---|---|
| durationUnit | tick / self_turn | tick = 墙钟递减；self_turn = 持有者自身行动机会数（机会括号左端扣 1） |
| duration | 正整数 / null | null = 常驻（Def 层声明）；0 = 一次性 |
| charges | 正整数 | 响应式派发 −1，归零卸载 |

## 触发器节流

- minIntervalTicks：同一触发器实例每 N tick 至多 fire 一次。
- maxTriggersPerBattle / oncePerBattle：每场限次。

## 触发链仲裁

> 节流管「单个触发器 fire 多频繁」，本节管「同刻多个触发器、以及链内派生事件谁先谁后、何时收敛」。

- **同刻全序**：同一刻 fire 的触发器按与 `on_battle_start` 相同的全序入队——载体归属 → 阵营 → (lane, index) → 触发器实例 id；同序不得并列。不引入第二套排序口径。
- **队列模型**：按全序入队、FIFO 消费；链内新产生的事件追加队尾、不插队（广度优先）。因此同刻结果不依赖结算先后，也不会因某条链持续派生而饿死其他链。
- **同链去重**：同一触发链内 `(event, carrierId, triggerInstanceId)` 三元组至多入队一次；重复即丢弃并写事件流留痕，杜绝 `on_apply → mount_status → on_apply` 自环。跨链同三元组不受限，否则「每 tick 挂同一状态」会被误杀。
- **两个硬上限**：单链深度与单 tick 全局触发预算由实现层设限，档位 **[PLACEHOLDER]**——属结构性安全常量，非平衡锚点；须由纸面原型按最坏链（同刻在场载体数 × 每载体触发点数）推出，带 rationale 并经试玩验证。**失败信号**：正常对局触达任一个上限即为设计 bug，不是调大档位能解决的问题。
- **超限处置**：不静默丢弃、不跨 tick 挂起；写异常事件进事件流，交 `战斗上下文.md` 终局节的僵局判据收口。挂起式续跑会让终局判定点失去「本 tick 已收敛」这个前提。
- **与冻结边界**：触发链不得改写已冻结的 Setup（INV-3）、不得回写 committedTargets（I 节点）；链内派生 Action 走同一 ActionSource 薄接口，EventTrigger 点火不消耗机会。
- **与随机 / 终局**：链内 chance 抽样仍受 R3 登记、R4 单次抽样、R5 非伤害维约束；触发链须在 tick 边界检查点前收敛，判定成立后按终局节冻结，不再补跑。
- **失败态**：同刻无全序 → 实现方各写一套、INV-2 复现破；链内不限深 → 死锁；超限静默丢弃 → 归因链断；跨 tick 挂起 → 终局判定点不成立。

### 多链竞态

> 上一节给「事件入队与消费次序」，本子节给「多条链落到同一运行态时的读写次序」。二者共用同一全序，不引入第二套排序口径；具体失效处置见 `../contexts/战斗上下文.md` §目标中途失效。

- **读当下运行态**：触发链在 O 节点读取的是**当前**运行态，不是本 tick 开始时的广播快照；只有决策期（I 节点）与定义态（Catalog / Setup）是快照。按全序 FIFO 消费，后一条链读到的是前序链已落地的结果。
- **读-改-写原子**：共享标量（战场量表、状态层数、连击计数、召唤位、规则槽、光照覆写栈）的读、改、写在同一原子步完成；不允许一条链读到值后被挂起、另一条链插入写入、再回写旧值（丢失更新）。
- **同一出口收敛一次**：对同一 `(targetId, statusId)` 的叠层 / 刷新、同一装备槽的顶替、同一界域栈顶的压栈，按各自状态机既定策略收敛；去重键是实例 id / 槽位 id，不是卡 id——同名状态的两个实例各自记账、各自撤销（INV-27），也不因多个触发器实例命中而重复结算两次。
- **事件与落地分离**：链内派生事件追加队尾不插队（见本节队列模型），其载荷结算时重新读取当下运行态；因此「事件产生的先后」不等于「数值读取的时点」。
- **与机会 / 终局**：触发链不消耗机会、不改写机会持有者（INV-26）；全部链须在 tick 边界检查点前收敛，终局判定成立后冻结，不再补跑（`../contexts/战斗上下文.md` 战斗终局）。
- **失败态**：按 tick 初快照广播 → 两条链的伤害互相看不见，同刻双亡变单亡，与「双方在场集合同时清空判平局」冲突；读改写非原子 → 同种子因实现层调度顺序不同得不同层数（INV-2 破）；按卡 id 去重 → 同名状态实例被误合并，溯源撤销失去依据。

## 调度（tick 推进与机会授予）

### tick 原子步

1. 时钟前进；2. 全部 Gauge.advance；3. Pool 按 regen 恢复；4. Channel.remaining--；5. Cooldown.remaining--；6. 状态与溯源账本时限条目 remaining--（到期回滚）；7. Zone 与 active 界域 duration 递减（被压制的上层界域不计时）；8. 收集本 tick 全部越阈 → 先手排序 → 依次授予机会。推进（1–7）与授予（8）严格分离；detached 单位不参与 2–6，回归后原样续走。

### 取值域

| 字段 | 取值 | 说明 |
|---|---|---|
| Gauge 触发条件 | 严格越过阈值（>，非 ≥） | 资格判定发生在跨过阈值的那 tick |
| overflowPolicy | Keep（越界留存） | 预留 Reset |
| 先手交替模式 | [己,敌,敌,己] 循环 | 双方各自按 (lane, index) 排序后交替合并，禁止按战场位置分层合并 |
| 冷却起点 | 提交时刻 | 引导期与冷却重叠 |
| 打断 | 资源不退 | 提交即承诺 |
| 行动周期 | 派生值 = threshold / rate | 禁止被 modify_stat 直接修正 |

### 数值基准

精力阈值 75（Gauge.threshold 与 cost.gaugeAmount 缺省，二者默认相等故默认行为不变）。cost.opportunity = 1（正常消耗机会）；0 = 本次 Action 不闭合机会，同一机会内免费 Action 至多 2 次（防无消耗循环），仍扣能量/冷却。

### 〇点五、回合 ↔ tick 换算基准

**1 回合 = 5 tick**（基准行动周期 = 75 / (15 + 8×敏捷)，敏捷 0 恰为 5 tick）。全部 duration 字段一律 **tick 存储**落库（durationUnit 只有 tick / self_turn 两值）；稿期「N 回合」口径按本基准换算，禁止把回合数 1:1 抄成 tick。self_turn 按持有者自身机会数递减：每次获得机会扣 1，与墙钟脱钩，detached 期间冻结；高敏捷单位行动周期 < 5 tick，「每回合触发」类效果自然更密（敏捷红利，不补偿）。modify_status 加时按目标状态自身的 durationUnit 口径填值（对 self_turn 状态填 2 = 加 2 个自身回合）。

### 机会括号字段契约

一次机会授予必产出一对事件：左端 `on_turn_start`、右端 `on_turn_end`，**两条事件都带 `opportunityId`**（= `unitId@tickIndex`，由 INV-26 保证同 tick 唯一）。`on_turn_end` 另带 `consumedBy`，订阅方据此区分「真出手」与空过。

| 闭合方式 | consumedBy | 条件 |
|---|---|---|
| 被 Action 消耗 | 该 Action id | Action 走完 O 节点后闭合 |
| wasted | 空 | 无可用行为 / 跳过 / 无资格 |

机会持有者已离场或不存在时不产出括号（无主体可挂事件），该机会直接记 wasted。机会括号是「每回合」类效果的唯一锚点：与 `on_tick`（墙钟）尺度不同，也与 `on_active_skill`（要求真出手且非普攻）外延不同。

资格校验（是否持有未消耗机会）与成本校验（Gauge 扣减量 + Pool 是否够）相互独立，前者由调度层判、后者由编队层判。
