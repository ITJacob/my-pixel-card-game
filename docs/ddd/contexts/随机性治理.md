# 随机性治理（Randomness Governance）

> 定位：`ddd/README.md`「随机性治理」节为摘要，本文件为细则。概率条件 chance 的取值域见 `params/共享内核参数.md` 谓词表。

## 一、确定性前提

完整确定性闭环 = Catalog 快照（INV-3，固定外部配置）+ 随机源治理（本篇，固定内部随机），二者合起来保证：结果 = f(初始状态, 输入次序, 种子)；三者相同则结果逐位相同（INV-2）。

## 二、治理规则（R1–R6）

| 规则 | 内容 |
|---|---|
| R1 | 默认零随机：伤害链、治疗、资源增减、目标选择，默认路径上不存在任何抽样 |
| R2 | 概率必须走 RandomSource：显式、可注入、可播种；种子在战斗创建时确定并写入战斗记录 |
| R3 | 登记制：引入概率的效果必须被显式标记，可被平衡审计工具筛出单列，逐个评审 |
| R4 | 单次抽样：随机源只在生效条件判定处被读取一次，禁止在结算链内部二次抽样 |
| R5 | 建议边界：概率只用于非伤害维度（是否挂载附加状态、触发哪条附加效果、spawn 质量/与否）；伤害/治疗数值保持确定；目标选择不引入随机 |
| R6 | 可复现契约：同初始状态、同输入次序、同种子，结果必须逐位相同 |

## 三、chance 条件的唯一合法用法

`EffectCondition.kind='chance'` 是唯一允许引入随机的条件，且必须经由 RandomSource（R2）。规范范例：「50% 概率挂灼烧」可以保留，但必须走 RandomSource 并登记为随机效果——判的是「效果是否生效」而非伤害数值，落在 R5 非伤害边界内；目标选择本身仍零随机（R1）。位格判定同理：必定生效分支不读随机源，低于门槛才以 `chance` 单次抽样。

- **互斥概率分支必须写成嵌套 if 链**（if→elif→else，各分支 condition 互斥、抽样只在判定处读一次，R4）；禁止并列多个独立概率 if（概率会叠加触发）。
- **落空/阻挡语义**一律用 charges 次数型状态的确定性写法，不开概率例外。
- **重排类效果**（行动条/状态轮转）是数值集合守恒重排，不产生新随机量。

## 四、随机效果登记册（R3 落点）

- **登记口径**：以 `condition.kind:'chance'` 机筛全库（cards + statusDefs 全嵌套），与本册逐条对齐；新增 chance 必须先入册再合卡。
- **册内字段**：效果 / 位置（文件 + 卡或状态 id）/ p / 抽样口径（单次，R4）/ 维度（非伤害，R5）/ 状态（登记或保留真随机及理由）。
- **多段独立伯努利**（如 8 段各 p=0.25）：每段各自单次抽样，允许保留真随机；退化方案（固定取段）不启用。
- **不入册**：charges 确定性写法、守恒重排、必定生效分支（不读随机源）。
- 本册随卡迁移逐批登记；机筛对账的权威是 schema 的 condition 定义。
